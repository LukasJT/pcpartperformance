## Integrate with the existing generator

Do not call the global generator from a content task. The parent build owns this insertion:

```js
const completionEditorial = require('./completion-editorial.cjs');
// After oct16-editorial, before guide-directory and the final SEO pass:
const result = completionEditorial(
  { root, records, shell, write, esc },
  { authorization: savedExactVersionOwnerRecord }
);
```

Prepare a new record only from the actual owner's release instruction, and persist it so later builds do not change release dates:

```js
const authorization = completionEditorial.authorizationFor({
  statement: actualOwnerInstruction,
  recordedAt: actualRecordingInstantInUTC,
  releaseDate: actualPreparedReleaseDayInToronto
});
```

The helper pins the exact article plus source-record hash. It validates consistency and honest attribution; it does **not** certify that a person read the prose. Unknown, duplicate or changed versions, future instants/days, a made-up reviewer, and a date before this research are rejected. An exact owner release is deliberately different from the original program's personal-review-attestation workflow. Do not fabricate an attestation in either system.

Without a release record, integration writes no new public article or search entries and returns a prepared/pending status. `PROGRAM_PREVIEW=1` or `{preview:true}` renders full private drafts with `data-program-draft`, no Article dates/schema and no search entries. Existing staging access controls and the final noindex pass still apply.

Preflight validates next-action destinations, canonical ownership and original publication history before writing. Material revisions preserve their real first-publication date. Relevant existing diagrams are retained when their asset exists. Rebuilding the same pinned version does not refresh its dates. The module merges metadata/search entries, preserves unrelated entries and removes only released routes from the original draft-exclusion list. It does not remove P39 or other unapproved drafts.

Release output is `owner_authorized_release_prepared` with `confirmedDeployment:false`. Only the parent release verification can establish that these exact pages are live. It must regenerate the guide directory and SEO, inspect the actual layouts and check links/indexing on staging and production as authorized.
