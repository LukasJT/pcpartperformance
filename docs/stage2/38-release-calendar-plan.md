# release calendar plan

Prepared October 4, 2026. Local release; deployment confirmation is not recorded.

No release-calendar dates were guessed from rumors. Proposed schema: exact product/software ID, event kind (announcement/availability/update), region, confirmed date or null, timezone, source URL/check date, confidence and revision history.

Only manufacturer-confirmed dates enter a public calendar. Keep a withdrawn date visible with a correction, not a silently moved event. An availability date differs from announcement and order date. Historical dates can support context but do not create fresh news.

Intake can queue candidates; editors verify the original document. Release alerts require an actual subscription service and consent. Until enough verified upcoming events exist, no thin calendar hub is indexed.
