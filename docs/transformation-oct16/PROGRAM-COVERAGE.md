## Concrete new destinations and improvements

- `/hardware/cpu-coolers/` and twelve exact cooler records: manufacturer specifications with explicit mounting/dimension limits, not invented catalog fillers.
- `/builder/`: Guided/Expert controls operate the same selection state; manual OS/accessory quotes stay separate from observed offers; the Passport records parts, costs and unresolved checks without a readiness percentage.
- `/upgrade/`: core and cooler/fan choices, multiple-instance handoffs and owned-part context use shared slot/rule identities. A scenario marks choices for review; it does not silently choose a replacement product or promise an uplift.
- `/my-pc/`: local saved-build continuity, notes, journal, manual quote records, watchlist and actual-observation differences. Details are in [WORKSPACE.md](WORKSPACE.md).
- `/search/`: deterministic routing for GPU fit, CPU/BIOS support, no-display and upgrade-first questions. Exact numeric requirements are retained; one-letter spelling help does not fuzzy-match numbers or substitute a nearby SKU.
- `/blog/how-to-choose-a-cpu-cooler-that-fits/`: new complete mounting/height/RAM/radiator decision guide.
- `/blog/build-vs-buy-pc-complete-cost/` and `/blog/will-a-graphics-card-fit-my-case/`: substantive improvements in place, with original publication dates preserved.

## What cannot be claimed complete

1. **Every component has an exact 3D model.** It does not. New cooler records deliberately remain inspectable without a mesh, and a model never certifies clearance or thermals.
2. **Every store has a live quote.** It does not. The fixed public-listing morning pipeline works for a small supported set. US and additional merchants require supported, exact, reproducible observations or authorized integrations. Retailer access restrictions are not bypassed.
3. **The FPS engine predicts measured performance.** It does not. There is no approved matching measured PC dataset. A test protocol, schema or source link is not a completed benchmark.
4. **All compatibility is automated.** It is not. Exact BIOS, installed cooling geometry, connectors/accessories and operating behavior can remain unresolved. Acknowledgement is not certification.
5. **Traffic or revenue improved.** No such measurement is available in this execution. Useful implementations, clean metadata and passing tests are not traffic evidence.
6. **The whole site is WCAG 2.2 AA or a perfect security/performance score.** That requires broader actual testing and ongoing maintenance; no blanket certificate is issued here.

## Measurement implementation versus reporting specification

`dist/program-events.js` already defines `PCP_EVENTS`: an allowlist, short safe enum-like parameters, a 750 ms duplicate guard and a required enabled/consented adapter. **No active analytics destination is configured.** It does not independently create page views, identify users or constitute a complete consent-management system.

| Event or KPI | Current state | Meaning to use |
| --- | --- | --- |
| `build_revision_saved` | Hook exists after a successful local save | A saved revision; not a purchased, physically compatible or complete build. |
| `build_shared` | Clipboard success and fallback-display hooks exist | Split by `action`. A fallback textarea is a sharing attempt, not a copied or visited link. Clipboard resolution is not proof another person opened it. |
| `guided_plan_updated` | Hook exists after the preferences plan is applied | Updated declared preferences, not an optimized recommendation. |
| `guide_builder_open` | Existing same-origin referrer hook at destination load | A supported guide-to-builder arrival when referrer is available; referrer loss creates undercounting. |
| Calculator/compatibility/upgrade result events | Existing allowlisted hooks/specification | Validate actual successful action points; a click or render must not be counted as a successful result. |
| Search, homepage intent, first selection, Passport open/download, workspace return/restore | Desired reporting definitions; complete collection is not asserted | Add only needed events through the existing adapter after configuration and consent QA, not an unrelated tracker. Never send query text, notes, part lists or local revision IDs. |
| Organic acquisition | No authorized Search Console data | Report actual non-branded clicks/impressions by page cluster, country and device when available; not public-search result counts. |
| Returning use and meaningful-progress rate | No measured baseline | Define a useful selected-list milestone and denominator before measuring. Counts based on browsers/devices/consent are not a perfect census of people. |

For every report, record date range, release annotation, country meaning, device grouping, consent coverage, bot/test exclusions and metric definition. Selected CA/US purchasing region is not proof of geographic location. Do not sum daily-user counts and call them unique people. Do not log full URLs with private/query state. Compare suitable 28-day/90-day periods and seasonality; do not attribute every difference to one code change. Google's Core Web Vitals guidance concerns real-user experience; local CPU timings, payload sizes and lab blocking time are not field INP.

The official GA4 user-definition page returned HTTP 429 during this pass, so no new report-field interpretation is inferred from that failed fetch. Current Google SEO/AI/CWV sources and their exact scope are recorded in [SEO-RESEARCH.md](SEO-RESEARCH.md).

## Evidence-backed quality rubric

Use **pass**, **partial**, **blocked** or **not yet verified** per actual receipt, rather than an averaged 10/10:

| Criterion | Evidence required before marking pass |
| --- | --- |
| Primary-task clarity | Desktop/mobile visitor can choose Build, Upgrade or Compare; example is labeled illustrative. |
| Builder/upgrade continuity | Cooler and multiple-instance changes survive handoff, old saved links and local restore; relevant compatibility results recalculate. |
| Trustworthy costs and checks | Unknown stays unknown; owned/manual/current/expired states remain distinct; no socket-only BIOS pass or geometry guarantee. |
| Retention/privacy | Save, return, duplicate, compare, notebook export/import and cancellation work; private notes stay outside public links and requests. |
| 3D reliability | Explicit lazy load, missing-model inspection, actual render, recoverable failure and preserved non-3D controls. |
| SEO/accessibility | Canonical/static HTML, accurate schema, correct draft/local-state exclusions, real keyboard/mobile checks and no important overflow. |
| Performance/security | Comparable payload/lab results, optional asset deferral, input/storage/import tests and no new secret or unsafe link handling. |
| Production readiness | Final full suite, reviewed changes, existing Git deployment, live commit marker and public route/API/browser checks. |
